# 개발자별 멤버 자격 관리 검증

검증일: 2026-10-14. 대상: `feature/managed-membership-qualifications`, 기존 자격 관리 commit `8e7a4e7` 이후 변경. **로컬 구현·검증 기록이며 운영 배포나 npm 게시 기록이 아닙니다.**

## 구현 범위

- 운영자 `/admin/roles`: 자격의 `개발자 선택 허용`을 명시적으로 설정. 기존 자격과 새 자격의 기본값은 비공개이며 PUT 옵션 생략은 기존 값을 보존합니다.
- 개발자 `/developer/apps`: 활성 개발자가 본인 소유 member 앱의 자격 ANY/ALL 또는 기본 조건 복원을 수행합니다. AUTH/기존 Connect 운영자는 기존 관리 범위를 유지합니다.
- 브라우저와 CLI API는 활성 사용자·개발자, 앱 소유권, 자격 공개·활성 상태를 서버에서 확인합니다. 브라우저 변경은 동일 Origin 및 JSON만 허용합니다.
- `qualifications list/status/set/reset`, init 번호 선택과 명시 옵션, sync 옵션, 관리 링크 제공. 옵션 생략은 기존 조건을 유지합니다.
- 자격 조회·질문·저장 실패 전에 앱 ID를 보존하므로 중복 등록 없이 재시도합니다. 보호 검증 전에는 기존처럼 설치 미완료를 반환합니다.
- README, 온보딩, LLM 지시문, 서버 보호 문서·명세를 새 계약으로 정리했습니다.

## 자동 검사

- `npm test`: 버전 일치 검사, release 검사 **22/22**, Worker/CLI 검사 **288/288** 통과(exit 0). 초기 실행은 새 자격 GET 응답을 제공하지 않은 기존 모의 서버 1건이 실패했으며, 실제 응답 형식을 fixture에 추가한 뒤 통과했습니다. 검증을 완화하지 않았습니다.
- 독립 리뷰에서 소유권 확인 후 저장 사이의 권한 회수 경합을 발견해 보강했습니다. INSERT와 DELETE 내부에서 현재 사용자 활성 상태·개발자/운영자 자격·소유권을 원자적으로 확인합니다. 소유권 삭제·개발자 비활성화·사용자 비활성화 × 두 저장 방식의 6가지 주입 사례에서 403, 정책 보존, 감사 이벤트 0건을 확인했습니다. 보강 후 관련 보안 회귀 **21/21** 통과(exit 0), 독립 재리뷰 승인입니다.
- API 검사는 두 소유자 간 격리, 비개발자·비활성 계정, 비공개·중지·미등록 자격 거부, 감사 기록, Origin, 자격 공개 취소·앱 기본 정책 변경 경합을 포함합니다.
- CLI 검사는 옵션 파싱·TTY 선택·ANY/ALL·현재 조건 보존·설정 실패 및 질문 취소 후 재시도·비대화형 조회 503 후 앱 재사용을 포함합니다.
- 기존 generated Worker/Pages의 실제 workerd 및 `protect verify` 검사, 비로그인 GET/HEAD/Range 차단, 사용자 지정 자격 통과 후 실제 공통 게이트의 이미지 300개 추가 `/me` 호출 0회 회귀를 포함합니다. 운영 사이트 전체 검사를 뜻하지 않습니다.
- `tsc --noEmit`, Wrangler `deploy --dry-run`, 로컬 CLI tarball 생성과 패키지 도움말 실행을 확인했습니다. dry-run은 배포하지 않습니다.

## 직접 사용 검증

### Chrome + 실제 SDK + 전체 AUTH 라우트 + 로컬 D1

일회성 localhost fixture를 사용했습니다. 실제 Discord 계정이나 운영 데이터를 사용하지 않았습니다.

1. 일반 개발자 SSO 연결 후 원래 `client_id=site` 복귀.
2. 다른 소유자의 앱이 목록에 없고, 공개된 간부·시즌4 두 자격만 표시.
3. ALL 저장, 새로고침 후 두 체크와 ALL 유지.
4. ANY 변경 저장, 빈 선택 저장 거부.
5. 기존 시즌3 조건 복원 및 새로고침 후 유지.
6. 운영자 화면에서 시즌4 자격의 개발자 공개 해제.
7. 개발자 화면에서 기존 선택 유지와 선택 불가 안내 확인; 허용된 간부 자격으로 교체 저장.
8. 최종 화면 레이아웃을 스크린샷으로 확인.

### 실제 CLI 프로세스 → HTTP → 전체 AUTH 라우트 → 로컬 D1

`list → status → set(all) → status → 비공개 자격 set 거부 → reset`을 실행하고 JSON 결과·종료 상태·저장 상태를 확인했습니다. 모의 fetch를 쓰지 않았습니다. 최초 fixture는 프로젝트 config version을 누락해 CLI가 정상적으로 거부했으며, fixture를 version 2로 수정한 뒤 전 과정이 통과했습니다.

## 호환성과 배포 경계

- 기존 보호 자산 요청의 공통 게이트 런타임은 변경하지 않았습니다. 기존 사이트의 정책은 명시적으로 저장하기 전까지 유지합니다.
- 공개 해제는 새 선택만 제한합니다. 기존 자격 사용을 중단하려면 자격 상태를 사용 중지하거나 해당 앱의 조건을 바꿉니다.
- 이미 발급된 게이트 lease에는 변경이 최대 1시간 뒤 반영될 수 있습니다. Discord 역할 스냅샷의 최대 24시간 신선도 계약도 유지합니다.
- 운영 적용은 공유 D1 migration 0016·0017, Cloudflare/Vercel AUTH 동시 버전 정렬, first-party callback 확인, CLI 신규 버전 게시가 필요합니다. 기존 게시 버전 0.7.5의 tarball을 같은 버전으로 덮어쓰면 안 됩니다.
- 운영 Discord OAuth, 실제 외부 개발자 계정, 운영 배포 후 smoke는 이번 로컬 작업에 포함하지 않았습니다.
