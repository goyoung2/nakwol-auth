# AUTH 0.2.10: authentication history and recovery visibility

- Admin app details support full retained history with category, period and Discord-ID filters, 50-row browsing, full JSON/CSV downloads, progress and cancellation.
- Read-time classification separates role/reauthentication refresh from permission denial and Discord authentication errors. Historical event rows remain unchanged. Legacy raw denial counters remain available for API compatibility.
- User views distinguish no success since the latest denial, current AUTH blocking, current refresh required, and historical recovery. Rows display current policy diagnosis and both timestamps. Cross-service success never resolves another app's failure history.
- Current-state filtering continues through candidate pages even when the first page has no matching users. Unknown-user errors remain in history; they are not attributed to guessed identities.
- Admin reads remain operator-only and no-store. No authentication hot-path, gate, SDK, lease, session TTL, schema or role-policy change. No npm publication or consumer-site reinstall needed.
