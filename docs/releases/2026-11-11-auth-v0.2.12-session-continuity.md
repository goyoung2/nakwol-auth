# AUTH 0.2.12 — service isolation and seven-day login continuity

An authorization failure on one service previously deleted the central SSO session,
forcing another permitted service back through Discord even immediately after login.
Both silent authorization denial and Discord callback denial now preserve an existing
central session. The denied app receives no authorization code or new session.
Every subsequent app authorization still checks the app's policy and user status.

The Discord role snapshot lifetime changes from 24 hours to seven days. Normal users
with retained browser cookies and unchanged permissions can reconnect during that
window using central SSO without Discord interaction. Site sessions and app tokens
remain capped at one hour and renew through SSO. Central idle/absolute limits remain
10/30 days. This is not a seven-day bearer token or a seven-day gate lease.

Explicit logout, operator revocation/reauthentication, disabled users/apps, and new
service policies still apply. Cookie deletion, another browser profile, and provider
outages are not suppressed or bypassed. Discord-only role removal may take up to
seven days plus the existing one-hour gate lease to affect access; operators should
use central revocation for earlier enforcement. No Discord bot or refresh token is
introduced. Existing installations using this AUTH need no gate/SDK reinstall.
The 24-hour role statements in the already-published Connect 0.7.8 gate specification
are superseded by this central AUTH policy; the gate runtime itself is unchanged.

Validation includes real AUTH handlers and Miniflare D1: A succeeds → B denies → A
reconnects, denied Discord callback preserves the existing login, fresh tokens and
/me succeed at 30 minutes/2 hours/1 day/3 days/just before seven days, and refresh is
required at the seven-day boundary. Disabled users and invalid cookies remain denied.
The initial regression test reproduced the old cookie/session deletion before the fix.

No DB migrations, SDK or npm changes. Roll back both runtimes to AUTH 0.2.11 if needed;
rollback restores the old 24-hour snapshot lifetime and session-deletion behavior.

Browser validation: Chromium used the actual AUTH handlers, isolated Miniflare D1,
unchanged gate 0.7.8, and deployed immutable SDK 0.3.4. After B denied access the
central cookie survived, A reconnected after its site cookie was removed, and a new
tab reconnected with a role snapshot aged seven days minus one minute. At seven days
the login button appeared and protected content was absent. Production Discord
accounts were not used or altered for these fixtures. Local full suite: 331 pass;
typecheck and Worker bundle dry-run pass.
