# 운영자 접근 문제 조치

서비스를 선택하면 접근 거부 사용자 목록이 표시됩니다. 최근 이벤트 50건과 독립적으로 authorize.access_denied / discord.login.access_denied 기록을 사용자별로 묶고 현재 정책으로 다시 진단합니다. 25명씩 페이지를 넘길 수 있습니다. 역할 문제가 있으면 행의 접근 허가 버튼으로 해당 서비스에만 예외를 부여합니다.

메모는 선택입니다. 생략해도 운영자, Discord ID, 서비스, 조치 종류, 시각과 기본 사유가 자동 기록됩니다. 해결된 사용자는 현재 접근 가능으로 표시하고 기존 거부 기록을 보존합니다.

사용자/서비스 비활성화, 운영자 정책, 재인증 요구를 수동 멤버 허가로 우회하지 않습니다. 본인 확인 전의 네트워크 실패는 이 목록에서 특정 사용자로 식별할 수 없으며 접속 진단과 이벤트 기록에서 확인합니다. 서비스 자체에서만 발생하고 AUTH에 도달하지 않은 실패는 이 목록에 없습니다.

검증: 실제 로컬 D1 10 tests pass, tsc --noEmit pass. 최근 성공 55건에 묻힌 거부 사용자, 27명 페이지네이션, 사유 없는 허가와 자동 감사, 다른 앱 권한 미변경, 비운영자 거부를 확인했습니다. 실제 admin HTML/JS를 브라우저에서 API fixture와 연결하여 메모 없이 행에서 허가한 후 현재 접근 가능으로 갱신됨을 확인했습니다. AUTH0.2.7로 양쪽 서버에 배포했습니다. 운영자 화면의 실제 거부 목록 조회를 확인했으며 운영 사용자에 대한 권한 변경은 수행하지 않았습니다.
