# 멤버 자격과 사이트별 접근 조건

## 관리 방법

1. AUTH 운영자로 `/admin/roles`에 접속합니다.
2. 자격 이름과 Discord 역할 ID를 등록합니다. 예: `시즌3 맹원`, `시즌4 맹원`, `간부`. 역할 ID는 Discord 개발자 모드에서 복사합니다. 봇은 필요하지 않습니다.
3. `/admin/apps`에서 사이트를 선택하고 접근 정책을 `멤버 자격 필요`로 저장합니다.
4. `허용할 멤버 자격`에서 자격을 선택합니다. `하나 이상(ANY)` 또는 `모두(ALL)`를 고르고 `선택한 자격 저장`을 누릅니다. 앱 기본 설정과 자격 조건은 별도 저장입니다.

선택한 자격은 기존 시즌3 필수 조건을 **대체**합니다. 시즌4만 선택한 사이트는 시즌4 역할만으로 입장할 수 있습니다. 시즌3와 간부를 모두 요구하려면 두 자격을 등록하고 ALL로 선택합니다. AUTH 관리자 권한은 자격으로 부여되지 않습니다.

자격을 선택하지 않은 기존 사이트와 새 설치의 기본값은 기존 시즌3 필수 조건입니다. 기존 추가 역할도 그대로 유지합니다. `/admin/roles/legacy`에서 기존 추가 역할을 편집할 수 있으며, 사용자 지정 자격이 적용된 앱은 이 화면에서 변경할 수 없습니다. `기존 시즌3 조건으로 복원`은 보존된 추가 역할까지 다시 적용합니다.

## 변경의 범위

- 자격 이름·역할 ID·사용 상태 변경은 해당 자격을 선택한 모든 사이트에 영향을 줍니다.
- 선택된 자격 중 사용 중지되거나 찾을 수 없는 자격이 있으면 ANY도 설정 오류로 차단합니다. 다른 자격만 남길 의도라면 먼저 해당 앱에서 선택을 해제하세요.
- 빈 선택은 저장할 수 없습니다. Discord 로그인 사용자 전체를 허용하려면 기존 조건으로 복원한 뒤 접근 정책을 `Discord 로그인 사용자`로 변경하세요.
- 사용자 지정 자격이 남은 채 다른 접근 정책으로 바꾸는 요청은 거부합니다. 관리자 화면과 CLI에 동일하게 적용됩니다.
- 운영자의 서비스별 수동 허가는 기존 예외로 유지됩니다. 앱·사용자 비활성화와 재인증 요구는 계속 적용됩니다.

## 서버 검증과 성능

중앙 AUTH는 Discord OAuth로 저장한 실제 서버 소속·역할 목록과 확인 시각을 검사합니다. 브라우저에서 보낸 자격 이름이나 역할 주장을 신뢰하지 않습니다. Discord 역할 정보는 기존처럼 로그인 시 갱신하며, 24시간 이상 된 정보는 재인증이 필요합니다.

`/me?client_id=...`의 `membership.is_member`는 명시적으로 사용자 지정 자격을 통과한 경우 **그 앱의 멤버 자격**을 나타냅니다. 이때 `membership.scope`는 `application`, `global_is_member`는 기존 전역 시즌3 판정이며 DB의 전역 역할을 변경하지 않습니다. 이 응답은 기존 Connect 0.7.5 member 게이트와 호환됩니다. 별도로 시즌3 역할 ID를 하드코딩한 외부 구현은 그 조건을 수정해야 합니다.

유효한 서버 세션의 자산 요청은 계속 로컬 암호 검증만 수행합니다. 자격 조회는 기존 중앙 권한 스냅샷 SQL에 포함되며 이미지마다 원격 DB나 `/me`를 호출하지 않습니다. 이미 발급된 권한 lease는 즉시 회수되지 않습니다. Connect 0.7.5의 기본 lease는 최대 1시간이며 토큰/세션 만료로 더 짧아질 수 있습니다. 자격 변경 후 신규 중앙 검증부터 새 조건이 적용됩니다.

## 배포 순서와 되돌리기

이 기능은 중앙 AUTH 변경입니다. SDK/npm 런타임 수정은 없습니다. 운영 배포 전에 공유 D1에 `0016_membership_qualifications.sql`을 적용하고 Cloudflare·Vercel AUTH를 같은 소스로 배포합니다. 마이그레이션은 새 테이블과 정책 충돌 방지 제약을 추가하며 기존 앱 조건을 자동 전환하지 않습니다.

두 서버 배포와 확인이 끝나기 전에는 사용자 지정 자격을 운영 사이트에 저장하지 마세요. 구버전 AUTH는 새 테이블을 무시하고 기존 시즌3 정책을 사용합니다. 롤백 시 자격을 사용하던 비시즌3 사용자가 차단될 수 있으므로 운영 자격 선택을 기록하고 조건을 복원한 다음 이전 중앙 서버로 되돌립니다. 새 테이블의 데이터는 보존합니다.
