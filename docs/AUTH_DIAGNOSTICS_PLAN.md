# Authentication diagnostics implementation

Status: implementation in `feature/auth-diagnostics`, based on released source tree `124c59d`.

## User requirements and scope

KT users report slow or failed authentication. The cause is unconfirmed. Provide a user-initiated diagnostic workflow and operator lookup, with evidence sufficient to distinguish site, central AUTH, Discord, policy, and network failures. Preserve required/member authorization and the local static-asset hot path.

### Task 1: implement diagnostics as one integrated feature

Ownership: source, common gate/CLI package, migrations, focused tests, version metadata, documentation. Do not deploy or publish. Do not edit immutable published SDK modules. Preserve all other worktrees. No subagents from implementer.

1. Add a self-contained shared browser diagnostic runtime in the Connect package, usable inline by generated login/recovery pages even when AUTH/SDK is unreachable. Provide a central `/diagnostics` page and diagnostics entry in existing central Embed/login failure UI. Use existing design tokens; responsive Korean copy, progress states, keyboard focus, timeout/cancel/retry, copy/download sanitized report, clear upload status and diagnostic number. Never claim a report was received without acknowledgement. Distinguish a local reference/report from a server reference if upload failed.
2. User-initiated probes: local site safe ping (if official gate installed), central AUTH lightweight probe, SDK module availability (without importing arbitrary scripts), and central DB/application lookup. Bound each probe and total duration. Run a few sequential/bounded checks, no unbounded retry. Measure HTTP status, elapsed time, safe network metadata observed by server, and which probe failed. CORS/timeout must be classified as an ambiguous browser observation, not proof of KT routing. Do not fetch arbitrary URLs, Discord private APIs, protected assets, or third-party diagnostic services. User agent/platform data may be coarse, no fingerprints/IP collection.
3. Offer an explicit diagnostic login retry that carries an opaque diagnostic ID through the normal PKCE flow. Record browser-observed `/token`, `/me`, and site `/__nakwol/session` durations using the SDK's existing fetch hook if possible; do not save request/response bodies, token, cookie, OAuth code/state, query/hash/return path or raw exception text. Report page-navigation vs request time separately. Human time at Discord is not AUTH latency.
4. Server instrumentation in the real OAuth flow: authorize, code exchange, Discord identity/member read, membership DB/policy, session/code creation, token/me. Use a small optional trace helper and exact stage/status enums; persisted server measurements are trusted, browser reports explicitly untrusted. Do not retry OAuth code exchange. Do not add probes or writes on normal static asset requests. Instrument opt-in diagnostic sessions only; persist bounded stages using asynchronous best-effort execution, and never let diagnostics persistence failure change authentication success/denial. For server-stage correlation across OAuth, a new nullable diagnostic reference column on oauth_requests is acceptable; never expose/store OAuth state/code in diagnostics.
5. Add additive D1 migration for reports/stages and rate limiting. Public writes need validated registered app+exact allowed origin, bounded payload and allowlisted fields, server-issued short-lived opaque capability/token bound to app/origin, hashed capability storage, write expiry, bounded stage/report counts and bounded persistent rate limits. Limit per requesting network and globally, hash any rate-limit address; retain reports 7 days and expire guards. Tickets are for diagnostics only, never authentication or authorization. Don't add a new production secret requirement: random hashed capabilities backed by D1 are acceptable. No remote fetch to user-supplied URLs. Limit request streaming bytes even without Content-Length. Reject unknown sensitive fields; do not store raw errors/URLs. No public report-read endpoint by reference. A user can download their locally generated sanitized report.
6. Add operator-only lookup/list API and UI in `/admin/apps` using existing admin section/DOM primitives. Use verified AUTH operator authorization (not an ordinary app session). Filter by selected app, lookup diagnostic reference, recent bounded reports, stage timeline with duration/status, browser-vs-server evidence labels, ASN/asOrganization/colo/CF-Ray when available. Never send other app's reports for a scoped request. Render all external fields with textContent. Distinguish empty/loading/error; invalidate stale results after switching app. No account data/secret content in report.
7. Official common gate is the only implementation. Add only explicit safe diagnostic endpoints (e.g. `/__nakwol/diagnostics`, `/__nakwol/diagnostics/ping`) containing operational diagnostic UI/ping and no protected assets; origin binding enforced. All other HTML/JS/CSS/JSON/image/font/download paths remain blocked unauthenticated for GET/HEAD/Range. Diagnostic route paths must not forward to ASSETS. Document public diagnostic exception. No added central AUTH/DB calls on an authenticated asset hit within lease.
8. Bump affected package versions without mutating immutable published SDK content (proposed AUTH 0.2.1 and Connect 0.7.3, update runtime/distribution/version table using project tooling). Explain existing installed server gates require normal protect update/build/deploy for local diagnostic entry; central new diagnostic route/admin and mutable Embed apply when AUTH is eventually deployed. No actual deployment in this task.
9. Tests: real Miniflare D1 migration + ticket issuance/expiry/app-origin scoping/rate limit/streamed body cap/sanitization/operator authorization/retention; OAuth correlation and trusted-stage capture under mocked Discord responses; persistence failure doesn't affect auth; browser runtime offline/cancel/progress/export; normal 300 asset lease has zero added AUTH calls and no diagnostic persistence. GET/HEAD/Range unauthenticated paths remain blocked. Existing contracts protect install/update/doctor/verify remain intact. Run focused tests then one full test/typecheck/Worker dry-run/managed smoke. Record actual results, not anticipated counts.
