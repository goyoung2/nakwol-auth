# 멤버 자격 관리 검증 기록

## 확인한 동작

- Miniflare D1 + 실제 AUTH 라우트: 전역 시즌3 역할이 없는 사용자도 앱에서 선택한 다른 자격으로 `/me` 통과. 전역 DB 역할은 `user`로 유지.
- ANY/ALL, 기본 시즌3, 추가 역할, 수동 허가, 재인증, 비활성 사용자·앱, 서버 미가입, 오래된 역할, 비활성·누락 자격을 검사.
- 실제 Connect 0.7.5 공통 게이트: 사용자 지정 자격으로 세션 발급 후 이미지 300건 허용. 최초 `/me` 1회, 이미지 요청의 추가 `/me` 0회.
- 무쿠키 HTML·이미지·JSON·JS·CSS·폰트 GET/HEAD/Range 차단. 다른 앱용 쿠키 재사용 차단. 자격 사용 중지 후 새 세션 발급 거부.
- 관리자 API의 토큰·운영자·Origin·입력 검증. 실제 SQLite/D1에서 기본 정책과 자격 저장의 경합을 재현하여 409와 트랜잭션 롤백 확인.
- 독립 리뷰에서 CLI 변경 경로와 쓰기 경합 2건을 발견, DB 트리거·409 처리로 수정. 재리뷰에서 추가 구체적 결함 없음.

## 브라우저 확인

Chrome에서 로컬 HTTP 서버가 실제 SDK·관리 화면·AUTH 라우트를 제공하고 Miniflare D1을 사용했습니다. 로컬 전용 진입 경로로 합성 운영자 SSO 세션을 설정했습니다. 운영 사용자·운영 DB는 변경하지 않았습니다.

확인: 자격 2개 등록 → 사이트 선택 → ALL 저장 → 페이지 새로고침 후 유지 → ANY 변경 → 빈 선택 저장 거부 → 기존 시즌3 조건 복원. 실제 Discord OAuth 승인 과정과 운영 배포는 이번 검증에 포함하지 않았습니다.

## 배포 상태

로컬 구현·검증 완료. 운영 Cloudflare/Vercel과 npm은 이번 기능으로 갱신하지 않았습니다. 운영 반영은 공유 D1 migration0016을 먼저 적용하고 두 AUTH 서버를 함께 배포해야 합니다. 기존 사이트 조건은 자동 변경하지 않습니다. 운영자가 자격을 적용할 사이트를 직접 선택합니다.
