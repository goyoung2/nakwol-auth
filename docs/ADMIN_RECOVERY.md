# 중앙 운영자 진단과 복구

T09의 로컬 구현 계약입니다. 운영 적용에는 AUTH 코드와 D1 migration `0019_admin_operations.sql`의 별도 배포가 필요합니다. 외부 개발자의 자기 서비스 사용자 관리 API는 D02에서 제공하며 이 중앙 API의 권한을 공유하지 않습니다.

## 진단과 조치

`/admin/apps`에서 서비스를 선택하고 Discord 사용자 ID 또는 사용자가 전달한 지원 코드를 조회합니다. 실제 접근 판정, 역할 마지막 확인, 중앙 SSO·앱 토큰·사이트 세션 기록, 런타임 보고 수신 시각을 구분합니다. 기록은 온라인 접속자 목록이 아닙니다. 서비스의 검사 보고는 중앙의 배포 증명도 아닙니다.

조치는 최근 15분 이내 Discord 운영자 재인증, 대상과 사유를 요구합니다. 자동 역할 갱신은 재인증으로 인정하지 않습니다. 영향 미리보기와 확인 뒤 버전을 비교해 저장하며, 충돌은 새로운 미리보기를 요구합니다. 동일한 요청의 재전송은 같은 조치 ID를 반환합니다.

| 조치 | 의미 |
|---|---|
| 기한부 허가 | 지정 앱의 수동 허가, 5분~7일. 계정 비활성·앱 비활성·명시적 차단을 우회하지 않음 |
| 허가 회수 | 수동 허가만 회수. 역할 조건을 충족하면 계속 접근 가능 |
| 차단 / 해제 | 앱 또는 중앙 범위의 명시적 차단. 허가보다 우선 |
| 역할 재확인 | 중앙에 보관한 본인 OAuth 자격으로 확인. 자격이 없으면 사용자 재인증 안내 |
| 사이트 세션 종료 | 지정 사용자·앱의 한 사이트 세션만 회수. 다른 앱과 중앙 SSO 유지 |
| 전체 재인증 요구 | 해당 사용자 중앙 가족·토큰 회수. 다른 서비스에도 영향 |
| 서비스 잠금 / 해제 | 지정 앱 비활성 / 활성. 인증·역할 조건 자체는 유지 |
| 이전 정책 복원 | 같은 앱의 정책 변경 전 상태를 새 버전으로 저장. 접근 조건을 낮추는 복원은 거부 |

중앙 관리 앱과 계정 복구 앱의 잠금, 마지막 운영자 중앙 차단은 거부합니다. 기존 `/admin/api/access/:clientId`의 grant/revoke/reauthenticate 의미는 유지하고 최근 재인증 검사를 추가했습니다. 이 호환 API는 신규 미리보기·CAS·중복 방지 계약을 제공하지 않습니다. 신규 연동은 `/admin/api/operations/:clientId/preview`와 확인 API를 사용하세요.

## 조치 상태를 읽는 방법

적용, 제어 문서 게시, 게이트 수신 확인은 별도 상태입니다. `pending`이면 AUTH의 원장은 바뀌었지만 제어 게시가 완료되지 않았습니다. 게시 실패는 전파 재시도로 복구하며 같은 사용자 조치를 반복하지 않습니다. 수신 확인은 특정 게이트의 기록이며 모든 브라우저에 반영됐다는 의미가 아닙니다.

외부 역할 재확인은 완료까지 `pending-refresh`로 기록합니다. 일시 실패는 `unavailable`, 다시 사용자 동의가 필요하면 `reauth-required`로 확정합니다. 실행 중단은 60초 실행 잠금 만료 뒤 같은 요청이나 역할 재확인 재시도로 재개할 수 있습니다. 중복 호출은 실행 잠금으로 합치며 이전 실행의 늦은 결과는 새 실행을 덮어쓰지 못합니다. 완료 시 해당 사용자 사이트들과 선택 앱에 이 조치가 소유한 제어 문서를 발행해 인과 receipt를 연결합니다. 외부 재확인 중 다른 앱의 조치를 자기 결과로 가져오지 않습니다.

이 콘솔은 사이트의 제어 프로필을 아직 확정하지 않으므로 `fastRevocationSupported=false`를 반환합니다. T08을 활성화한 공식 게이트의 35초 상한은 **제어 게시 이후** 기준입니다. 일반 local-lease의 최대 재검증 간격은 300초입니다. 런타임·제어 키 설정이 확인되지 않은 기존 사이트를 신속 차단 지원으로 표시하지 않습니다.

## 일회성 복구 코드

최근 운영자 재인증 후 선택 앱과 사유를 지정해 발급합니다. 필요하면 같은 앱의 이전 정책 조치 ID도 지정합니다. 코드는 10분 유효하고 한 번만 사용할 수 있으며 DB에는 해시만 보관합니다. URL·로그·브라우저 저장소에 넣지 마세요. 콘솔의 비밀번호 입력란으로 한 번 전달되며 앱 전환 시 지워집니다.

`/admin/recovery`에서 코드를 입력하면 발급 당시 앱의 잠금 해제 또는 지정 정책 복원을 수행합니다. 회원 역할·운영 권한·콘텐츠 접근 토큰을 부여하지 않습니다. 운영자 권한이 회수됐거나 코드가 만료·사용된 경우 거부합니다. 발급과 사용에 속도 제한 및 감사 기록을 적용합니다.

지원 코드는 비밀 자격 증명이 아닙니다. 계정 복구 화면은 본인 접근 실패 코드만 표시하며 다른 사용자의 상세 역할·세션 정보는 반환하지 않습니다. 운영자가 선택 앱 안에서만 지원 코드를 조회할 수 있습니다.

## 코드가 없거나 중앙 인증 서비스가 동작하지 않을 때

호스팅 관리 계정으로 접근해야 합니다. 인증 화면을 제거하거나 보호 자산을 공개해서 복구하지 마세요.

1. 배포 ID, 시간, 오류, 최근 정책 조치 ID와 원장 상태를 기록합니다. 비밀값과 사용자 자료는 기록하지 않습니다.
2. 직전 검증된 AUTH 배포를 호스팅 콘솔에서 복구합니다. 이번 additive migration의 테이블을 삭제하거나 DB 전체를 과거로 덮어쓰지 않습니다.
3. 정책 오류라면 DB를 백업하고 해당 앱의 감사 기록 `before_json`과 현재 정책을 대조합니다. 복구 콘솔이 살아 있으면 새 복원 조치를 사용합니다. 중앙 자체가 잠긴 경우 소유자가 관리하는 호스팅·D1 경로에서 정책을 최소 범위로 복구하고 이유·전후 상태를 별도 기록합니다.
4. 서버 게이트와 비공개 원본 자산 설정을 유지합니다. signing key/site credential 회전은 이전 공개 키와 배포 의존성을 확인한 뒤 별도 작업으로 진행합니다.
5. 비로그인 GET/HEAD/Range, HTML·JSON·이미지·다운로드 차단을 `protect verify`로 재검사하고, 정상 회원의 로그인·새로고침·로그아웃을 실제 브라우저에서 확인합니다.
6. 제어 원장과 outbox의 pending/failed를 확인하여 게시를 재시도합니다. 소스 복구만으로 권한·정책 원장이 복원된 것으로 판단하지 않습니다.

전역 시즌3 기준 변경, owner 관리, 계정 비활성 복구는 이 코드의 권한 밖입니다. 필요한 경우 중앙 운영자의 별도 관리 절차를 사용합니다.

현재 영향 미리보기의 세션 수는 사용자·앱 범위 기준입니다. 단일 세션 종료 또는 아직 가입하지 않은 Discord ID의 조치에서는 실제 영향보다 크게 표시될 수 있습니다. 대상 귀속과 실제 변경 조건은 서버에서 별도로 검증합니다.
